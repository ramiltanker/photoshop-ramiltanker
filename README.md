# Редактор изображений

Веб-приложение для обработки изображений. Лабораторные работы по дисциплине
«Обработка изображений».

**Приложение на хостинге:** https://ramiltanker.github.io/photoshop-ramiltanker/

## Возможности

- Загрузка изображений в форматах PNG, JPEG и GrayBit-7 (GB7) — через диалог выбора
  файла или перетаскиванием в рабочую область.
- Отрисовка изображения на HTML5 `<canvas>` с вписыванием в окно при загрузке.
- Строка состояния с именем файла, форматом, шириной, высотой, глубиной цвета,
  размером файла и регулятором масштаба отображения.
- Сохранение в PNG, JPEG (с выбором качества) и GB7 (с записью бита маски).
- Панель цветовых каналов с миниатюрами и переключением видимости.
- Пипетка: координаты пикселя, значения RGB и координаты цвета в CIELAB.
- Градационная коррекция «Уровни» с гистограммой и предпросмотром.
- Масштаб отображения от 12 до 300 % и изменение размера изображения собственными методами интерполяции.
- Фильтрация свёрткой с ядром 3 × 3: преднастроенные ядра, выбор каналов и обработки края.

Формат определяется по сигнатуре файла, а не по расширению.

## Формат GrayBit-7

Кодер и декодер GB7 написаны с нуля, без сторонних библиотек.

Заголовок занимает 12 байт:

| Смещение | Размер | Поле                         |
| -------- | ------ | ---------------------------- |
| 0        | 4      | Сигнатура `47 42 37 1D`      |
| 4        | 1      | Версия (`0x01`)              |
| 5        | 1      | Флаги, бит 0 — наличие маски |
| 6        | 2      | Ширина, big-endian           |
| 8        | 2      | Высота, big-endian           |
| 10       | 2      | Резерв                       |
| 12       | W × H  | Данные изображения           |

Каждый пиксель — один байт: биты 0–6 хранят градацию серого (0–127), бит 7 —
бит маски (1 — пиксель виден, 0 — прозрачный), значимый только при взведённом
флаге маски.

При декодировании градация растягивается до диапазона 0–255, при кодировании
цвет приводится к яркости по формуле `0.299 R + 0.587 G + 0.114 B` и
квантуется обратно до 7 бит. Декодирование и кодирование взаимно обратны:
повторное сохранение открытого GB7-файла даёт побайтово тот же файл.

## Цветовые каналы

Набор каналов определяется цветовой моделью исходного файла, а не содержимым
растра:

| Каналов | Когда                  | Пример                                                |
| ------- | ---------------------- | ----------------------------------------------------- |
| 1       | оттенки серого         | GB7 без маски, PNG с color type 0, одноканальный JPEG |
| 2       | оттенки серого и альфа | GB7 с маской, PNG с color type 4                      |
| 3       | RGB                    | PNG с color type 2 или 3, трёхкомпонентный JPEG       |
| 4       | RGB и альфа            | PNG с color type 6                                    |

Миниатюры всех каналов показаны в градациях серого: белый означает максимум
интенсивности канала, чёрный — его отсутствие. Клик по каналу включает или
выключает его отображение, состояние видно по рамке, подписи и значку.

Отключённый цветовой канал обнуляется при выводе, отключённый альфа-канал
делает изображение полностью непрозрачным. Если выключены все цветовые каналы,
а альфа оставлен, на холст выводится маска прозрачности в градациях серого.

Исходный массив пикселей никогда не изменяется: под вывод собирается новый
буфер, поэтому переключение каналов обратимо без повторного чтения файла.
Миниатюры считаются один раз на изображение — сначала оно уменьшается
усреднением по площади, затем каналы извлекаются уже из уменьшенной копии.

## Пипетка

Инструмент включается кнопкой в панели инструментов. Клик по холсту переводится
в индекс пикселя с учётом того, что холст растянут средствами CSS: используется
отношение реального размера изображения к размеру элемента на странице, поэтому
координаты точны при любом масштабе отображения.

Показываются координаты X и Y относительно изображения, значения R, G и B в
диапазоне 0–255, значение альфы и координаты цвета в CIELAB. Перевод выполняется
самостоятельно: sRGB линеаризуется, переводится в XYZ по матрице D65 и затем в
L\*a\*b\* относительно белой точки D65. Значения берутся из исходного
изображения и не зависят от того, какие каналы включены.

## Гистограмма и уровни

Инструмент «Уровни» открывается в нативном элементе `<dialog>`, показанном
методом `showModal`.

Гистограмма строится по 256 уровням. Для режима Master светлота пикселя
считается как `0.299 R + 0.587 G + 0.114 B` — той же формулой, что используется
при кодировании в GB7. При выборе конкретного канала гистограмма
перестраивается по значениям только этого канала, включая альфу. Шкала
ординат переключается между линейной и логарифмической: во втором случае
высота столбца пропорциональна `ln(1 + n)`, что позволяет разглядеть
распределение, когда один уровень сильно преобладает над остальными.

Гистограмма изображения GB7 выглядит гребёнкой: формат хранит 7 бит на
пиксель, поэтому после растяжения в диапазон 0–255 занятыми оказываются
только 128 уровней. Это не артефакт отрисовки, а точное отражение данных.

Под гистограммой расположены три маркера входных уровней. Точка чёрного не
может зайти за точку белого и наоборот, маркер полутонов всегда остаётся
между ними. Хранится не положение маркера полутонов, а значение гаммы, а
положение вычисляется из него: `p = black + (white - black) * 0.5^gamma`.
Поэтому при сдвиге крайних точек гамма не меняется. Обратный перевод —
`gamma = ln(p) / ln(0.5)` с ограничением диапазоном 0.1–9.9, где 1.0 даёт
линейное отображение, сдвиг влево осветляет средние тона, вправо затемняет.

Преобразование уровня выполняется по формуле

```
t = (value - black) / (white - black), ограничено диапазоном 0..1
out = 255 * t^(1 / gamma)
```

Значения не считаются для каждого пикселя: по параметрам строится таблица
подстановки (LUT) на 256 элементов для каждого канала, и обработка сводится
к выборке из массива. Настройки Master и отдельного канала объединяются
композицией таблиц — сначала применяется таблица канала, затем общая.
Настройки хранятся отдельно для Master и каждого канала, поэтому при
переключении в выпадающем списке они не теряются. Master действует на
цветовые каналы и не затрагивает альфу.

Предпросмотр включён по умолчанию и обновляется с троттлингом: пересчёт
запускается не чаще одного раза в 60 мс, последнее изменение применяется
обязательно. Снятие флажка мгновенно возвращает холст к состоянию до
открытия диалога. «Сброс» возвращает значения к исходным, не закрывая окно,
«Отмена» закрывает окно и отменяет изменения, «Применить» записывает
результат в изображение, после чего с ним работают панель каналов, пипетка
и сохранение.

## Интерполяция и масштаб

Реализованы два метода двумерной интерполяции: ближайший сосед и билинейная.
Браузерное масштабирование изображения нигде не используется — и отображение
на холсте, и изменение размера проходят через эти реализации. По умолчанию
используется билинейная.

Метод описывается объектом с идентификатором, названием, кратким описанием и
функцией, которая заполняет одну строку результата. Цикл по строкам, разбиение
на порции и отчёт о прогрессе общие, поэтому новый метод добавляется одним
файлом и одной записью в реестре `interpolation/registry.ts`.

Координата в исходном изображении считается от центра пикселя:
`src = (dst + offset + 0.5) / scale - 0.5`. Ближайший сосед округляет её, билинейная
берёт четыре соседних пикселя с весами по расстоянию. Цвет смешивается с учётом
альфы: каналы умножаются на прозрачность до интерполяции и делятся после, иначе
на границе с прозрачной областью проступал бы цвет скрытых пикселей.

Масштаб отображения задаётся регулятором в строке состояния от 12 до 300 %.
При загрузке файла изображение вписывается в область холста с отступами не
меньше 50 пикселей, результат ограничивается тем же диапазоном. Пока масштаб не
менялся вручную, вписывание пересчитывается при изменении размера окна.

На холст отрисовывается только видимая часть изображения: область прокрутки
получает полный размер, а холст остаётся размером с окно и перерисовывается при
прокрутке. Без этого изображение 3840×2160 на 300 % потребовало бы буфер около
300 МБ. Отрисовка идёт в физических пикселях экрана с учётом плотности пикселей,
но не больше двукратной.

Инструмент «Размер» открывает модальное окно с числом мегапикселей до и после,
выбором единиц (пиксели или проценты), шириной и высотой, связью пропорций,
выбором алгоритма и подсказкой с его описанием. Ввод проверяется: значение должно
быть числом больше нуля, в пикселях — целым, сторона результата от 1 до 10 000
пикселей, площадь не больше 50 мегапикселей. После подтверждения изображение
пересчитывается из текущего в новый размер и показывается с тем масштабом, что
выставлен в строке состояния.

Все модальные окна приложения построены на одном компоненте
`shared/components/ModalDialog.tsx` поверх нативного `<dialog>`. Выпадающие списки
и подсказки внутри них рендерятся без портала: модальный `<dialog>` находится в
верхнем слое страницы, и элементы, вынесенные в `body`, оказались бы под его
подложкой.

## Фильтрация свёрткой

Инструмент «Фильтр» открывает модальное окно с сеткой 3 × 3 для коэффициентов
ядра, списком преднастроенных ядер, выбором каналов, выбором обработки края,
флажком предпросмотра и кнопками «Сбросить», «Закрыть» и «Применить».

Преднастроенные ядра:

| Ядро                             | Коэффициенты                            |
| -------------------------------- | --------------------------------------- |
| Тождественное отображение        | `0 0 0 / 0 1 0 / 0 0 0`                 |
| Повышение резкости               | `0 -1 0 / -1 5 -1 / 0 -1 0`             |
| Фильтр Гаусса 3 × 3              | `1 2 1 / 2 4 2 / 1 2 1`, делённые на 16 |
| Прямоугольное размытие           | все девять по 1/9                       |
| Оператор Прюитта, по горизонтали | `-1 0 1 / -1 0 1 / -1 0 1`              |
| Оператор Прюитта, по вертикали   | `-1 -1 -1 / 0 0 0 / 1 1 1`              |

Выбор ядра заполняет ячейки, после чего их можно править. В ячейку можно ввести
число или дробь вида `1/9` — так ядра размытия задаются точно, без округления.
Если значения совпадают с одним из ядер, в списке показывается его название,
иначе — «Пользовательское ядро». Под сеткой выводится сумма коэффициентов: при
сумме 1 яркость сохраняется, при 0 остаются только перепады. Ячейка должна
содержать число по модулю не больше 1000, делитель дроби не может быть нулём.

Перед свёрткой изображение расширяется на один пиксель с каждой стороны по
выбранной стратегии: чёрным, белым или копированием ближайшего краевого
пикселя. Поэтому размер результата совпадает с исходным. Затем для каждого
пикселя и каждого выбранного канала считается взвешенная сумма девяти соседей;
значения за пределами 0–255 обрезаются. Невыбранные каналы копируются без
изменений. Набор каналов берётся из цветовой модели: у цветного изображения это
красный, зелёный и синий, у полутонового — яркость, плюс альфа, если она есть.
По умолчанию выбраны все цветовые каналы без альфы.

Обработка идёт асинхронным циклом: изображение обрабатывается порциями строк,
между порциями управление возвращается браузеру, поэтому интерфейс остаётся
отзывчивым, а полоса прогресса показывает ход работы. Предпросмотр
пересчитывается с троттлингом, а незавершённый пересчёт прерывается через
`AbortSignal`, как только параметры меняются снова, — устаревшие результаты не
накапливаются. Троттлинг и отмена вынесены в общий хук, которым пользуются и
«Уровни», и фильтр.

## Глубина цвета

Глубина цвета читается из заголовка исходного файла собственными разборщиками,
а не берётся из готового растра браузера:

- PNG — поля `bit depth` и `color type` из чанка `IHDR`;
- JPEG — точность и число компонент из маркера кадра `SOFn`;
- GB7 — 7 бит градации плюс бит маски, если она есть.

## Структура

```
src/
  app/                     тема и провайдеры приложения
  core/image/              работа с изображениями, не зависит от интерфейса
    constants.ts           параметры пиксельного буфера
    types.ts               модель изображения и метаданных
    rasterImage.ts         операции над буфером RGBA
    colorDepth.ts          описание глубины цвета
    colorModel.ts          определение цветовой модели и наличия альфы
    loadImageDocument.ts   загрузка файла в модель
    saveImageDocument.ts   выгрузка модели в файл
    channels/              модель каналов, композиция вывода, миниатюры
    color/                 яркость, перевод в CIELAB, чтение пикселя
    filters/               ядра свёртки, расширение края, применение фильтра
    histogram/             расчёт гистограммы по каналу или яркости
    interpolation/         методы интерполяции, реестр, пересчёт размера
    levels/                параметры уровней, таблицы подстановки, применение
    processing/            построчная обработка и уменьшение изображения
    formats/
      detectFormat.ts      определение формата по сигнатуре
      browserCodec.ts      PNG и JPEG средствами браузера
      gb7/                 собственные кодер и декодер GrayBit-7
      png/                 разбор заголовка PNG
      jpeg/                разбор маркеров JPEG
  features/editor/         экран редактора: компоненты, состояние, вьюпорт
  shared/                  общее модальное окно, хуки и утилиты
```

Обработка идёт построчно, порциями, с уступкой потока между порциями: интерфейс
не блокируется, а в строке прогресса видно продвижение по крупным изображениям.

## Деплой

Сборка публикуется на GitHub Pages при пуше в `main`
(workflow `.github/workflows/deploy.yml`). Базовый путь задаётся параметром
`base` в `vite.config.ts` и совпадает с именем репозитория.
